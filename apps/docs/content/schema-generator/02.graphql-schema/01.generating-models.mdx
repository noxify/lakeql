## Overview

The `generateModel` function recursively walks a JSON Schema (Draft-07) representation of a table's columns and produces a set of `ModelResponse` objects. Each model describes a GraphQL type with its fields, type mappings, transform information, and filter eligibility.

## generateModel Function

```typescript
import { generateModel } from "@lakeql/schema-generator/graphql-schema"
import type { JSONSchema7 } from "json-schema"

const models = generateModel({
  source: jsonSchema, // JSONSchema7 representing the table structure
  name: "Order", // Name for the root model
  models: {}, // Accumulator for recursive calls
  isRoot: true, // Whether this is the top-level model
})
```

## ModelResponse Interface

```typescript
interface ModelResponse {
  root: boolean
  modelName: string
  interfaceName: string
  fields: Record<string, CurrentModelResponse>
  transformFields: string[][]
  dateTimeFields: string[]
}

interface CurrentModelResponse {
  name: string
  rawFieldName: string
  transformed: boolean
  interfaceType: string
  graphqlType: string
  graphqlTplType: string
  isArray: boolean
  interfaceName?: string
  nullable: boolean
  filter: boolean
}
```

| Field             | Description                                                               |
| ----------------- | ------------------------------------------------------------------------- |
| `root`            | Whether this is the top-level model                                       |
| `modelName`       | The model name used in generated GraphQL types                            |
| `interfaceName`   | TypeScript interface name (appends `Interface`)                           |
| `fields`          | Map of field name → field metadata                                        |
| `transformFields` | Array of `[graphqlName, dbColumnName]` pairs for fields that were renamed |
| `dateTimeFields`  | Field names that have `DateTime` type (for `to_unixtime()` wrapping)      |

## Field Type Mapping

The generator maps JSON Schema types to GraphQL types:

| JSON Schema Type | Format      | GraphQL Type | Filter |
| ---------------- | ----------- | ------------ | ------ |
| `string`         | —           | `String`     | Yes    |
| `string`         | `date`      | `Date`       | Yes    |
| `string`         | `date-time` | `DateTime`   | Yes    |
| `number`         | —           | `Float`      | Yes    |
| `integer`        | —           | `Int`        | Yes    |
| `boolean`        | —           | `Boolean`    | Yes    |
| `array`          | —           | `[Type]`     | No     |
| `object`         | —           | Nested model | No     |

## Recursive Model Generation

When a field has type `object` or `array` of objects, the generator recursively creates a sub-model. Nested model names are constructed by combining the parent name with the field name:

```typescript
// For a table "Order" with a nested "address" field:
// Root model: "Order"
// Nested model: "Order_Address"
// Deeper nesting: "Order_Address_Coordinates"
```

## Field Name Transformation

Special characters in column names are handled automatically:

- Hyphens (`-`) and dots (`.`) are replaced with underscores
- Fields starting with a digit get a leading underscore prefix
- The original name is preserved in `rawFieldName` for SQL generation
- The `transformed` flag indicates whether renaming occurred

```typescript
// Column "order-date" becomes field "order_date"
// Column "3d_model" becomes field "_3d_model"
// Both track the original name in transformFields
```
