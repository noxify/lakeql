With the environment configured, generate an endpoint and start the server.

## Generate an Endpoint

Introspect a table and generate its typed files with [`pull`](/docs/cli/commands/pull):

<Command variant="exec">lakeql-cli pull --env .env</Command>

Run interactively, it prompts for the source, schema, and table; or pass them as options. The generated files land under your configured source path. See [Key Concepts](/docs/lakeql/introduction/key-concepts) for the layout.

## Start the Server

Start the generated dev script:

<Command variant="run">dev</Command>

This runs the scaffolded `dev` script (`node --env-file=.env --import tsx ./src/index.ts`), which loads the generated schema and serves GraphQL at `/graphql`, with a health check at `/live`.

Check that the server started — a request to `/live` is expected to succeed, and the query below is expected to run against your generated type. (Exact response bodies depend on your data and are not asserted here.)

## Run a Query

Open the GraphQL endpoint and run a query against your generated type:

```graphql
query {
  orders(paging: { page: 1, perPage: 10 }) {
    nodes {
      id
      status
    }
    pageInfo {
      hasNext
      currentPage
    }
  }
}
```

<Success title="You're running">
  You now have a type-safe GraphQL API over your data source. From here, add
  more endpoints with `pull`, or explore the [guides](/docs/lakeql/guides).
</Success>
