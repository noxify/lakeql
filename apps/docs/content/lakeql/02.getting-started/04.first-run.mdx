Once the environment is configured, generate an endpoint and start the server.

## Generate an Endpoint

Introspect a table and generate its typed files with [`pull`](/docs/cli/commands/pull):

<Command variant="exec">lakeql-cli pull --env .env</Command>

<Note>
  A scaffolded project installs `@lakeql/cli` as a dev dependency, so the
  command runs the local binary by default. Toggle **Run without installing** on
  any exec command to get the one-off form through `pnpm dlx @lakeql/cli` or
  `npx @lakeql/cli`, which fetches the package for a single run.
</Note>

Run it interactively and it prompts for the source, schema, and table. You can also pass them as options. The generated files land under your configured source path. See [Key Concepts](/docs/lakeql/introduction/key-concepts) for the layout.

## Start the Server

Start the generated dev script:

<Command variant="run">dev</Command>

This runs the scaffolded `dev` script (`node --env-file=.env --import tsx ./src/index.ts`). The script loads the generated schema and serves GraphQL at `/graphql`, with a health check at `/live`.

Check that the server started. A request to `/live` succeeds, and the query below runs against your generated type. Exact response bodies depend on your data, so they are not asserted here.

## Run a Query

Open the GraphQL endpoint and run a query against your generated type:

```graphql
query {
  orders(
    sorting: [{ field: id, direction: ASC }]
    paging: { page: 1, perPage: 10 }
  ) {
    nodes {
      id
      status
    }
    pageInfo {
      hasNext
      currentPage
    }
  }
}
```

<Note>
  `sorting` is required on every generated query. It gives the engine a
  deterministic `ORDER BY`. This keeps offset-based paging stable, so pages do
  not repeat or skip rows. See [Sorting &
  Paging](/docs/packages/query-builder/sorting-and-paging) for why.
</Note>

<Success title="You're running">
  You now have a type-safe GraphQL API over your data source. From here, add
  more endpoints with `pull`, or explore the [guides](/docs/lakeql/guides).
</Success>
