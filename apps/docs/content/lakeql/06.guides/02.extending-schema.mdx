navTitle: Extending the Schema
description: Add a computed or related field to a type you pulled.
---

Custom resolvers add new root fields. Sometimes you instead want a field on a type you already pulled. You can add a computed `displayName` to a generated `Order`, or a related field that reaches another source.

This guide walks through one worked task: add a computed `displayName` to a generated `Order` type.

<Warning title="Keep extensions out of the generated directory">
  Re-running [`pull`](/docs/cli/commands/pull) recursively deletes and recreates
  the endpoint's per-table generated directory
  (`schemas/generated/<dataSource>/<catalog>/<schema>/<table>`). Anything you put
  in that directory is lost on the next pull. Keep your extensions in your own
  modules.
</Warning>

<Steps>

<Step>Find the generated reference</Step>

Locate the generated object reference for the type you want to extend, such as `OrderRef`. It lives in the generated files for that table under `schemas/generated`. You import it to tell the builder which type the new field belongs to.

<Step>Create your own module</Step>

Put the extension in a file you own, such as `src/extensions.ts`. Do not edit the generated files, because a later `pull` deletes that directory.

```ts
// src/extensions.ts
import { builder } from "@lakeql/api/builder"
```

<Step>Add the field</Step>

Extend the generated type with `builder.objectField`. The resolver receives the parent object, so you can compute the value from its fields.

```ts
// src/extensions.ts
import { builder } from "@lakeql/api/builder"

builder.objectField(OrderRef, "displayName", (t) =>
  t.string({
    resolve: (order) => `#${order.id} — ${order.status}`,
  })
)
```

The field participates in the same schema as the generated ones. It shares the scope-auth scopes, the scalars, and the validation plugin. See [extending core](/docs/api/customization/extending-core) for the full `objectField` mechanics.

<Step>Import the module before you start the server</Step>

Add the import to your entry point, before the call to `startServer()`. The server only registers modules it imports.

```ts
import "./extensions"

await server.startServer()
```

See the [two prerequisites](/docs/api/customization/custom-queries-mutations#two-prerequisites) for the discovery rule.

<Step>Run it</Step>

Start the dev server and query the new field.

<Command variant="run">dev</Command>

```graphql
query {
  orders {
    id
    status
    displayName
  }
}
```

</Steps>

## Reach another source

A field on a generated type can also read from a different source. Resolve it through the context accessor, the same one custom resolvers use.

```ts
builder.objectField(OrderRef, "customer", (t) =>
  t.field({
    type: CustomerRef,
    resolve: async (order, _args, context) => {
      const strategy = context.getReadStrategy("crm")
      // read the related record with the strategy
      // ...
    },
  })
)
```

This keeps the join in your own module, so a later `pull` leaves it untouched.
