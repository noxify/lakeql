The generated endpoints cover table reads and writes. You will often need fields that are not a direct table query, such as an aggregate, a computed value, or a call to another service. Add these on the shared schema builder.

```ts
import { builder } from "@lakeql/api/builder"

builder.queryField("orderCount", (t) =>
  t.int({
    resolve: async (_root, _args, context) => {
      // reach data via the context accessors: getReadStrategy / getWriteStrategy
      const strategy = context.getReadStrategy("warehouse")
      // ...
      return count
    },
  })
)
```

This is the same [`builder`](/docs/api/schema-builder/builder-configuration) the generated endpoints use. So your custom fields get the same auth scopes, input validation, and scalar types.

<Note>
  Two prerequisites apply. Import the module that registers your fields before
  `startServer()`. The `Mutation` root type exists only when the project has a
  generated mutation. See [custom queries &
  mutations](/docs/api/customization/custom-queries-mutations#two-prerequisites).
</Note>

## Authorization and Validation

Declare required scopes through the field's `authScopes` option. See [scope authorization](/docs/api/authentication/scope-authorization). Validate arguments with a Zod schema via `validate`. See [input validation](/docs/api/schema-builder/input-validation).

For the full details and the mutation case, see [custom queries and mutations](/docs/api/customization/custom-queries-mutations).
