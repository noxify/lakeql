## Requirements

Before working on LakeQL, make sure you have the following tools installed:

- [Node.js](https://nodejs.org/) v24 or later (see `.nvmrc`)
- [pnpm](https://pnpm.io/) v11+ (declared in `packageManager` field)
- [Docker](https://www.docker.com/) — container runtime for the local Trino cluster
- [uv](https://docs.astral.sh/uv/) — Python package manager (required for minitrino)

## Quick Start

<Steps>

<Step>Clone and install</Step>

Clone the repository and install dependencies:

```bash
git clone https://github.com/noxify/lakeql.git
cd lakeql
pnpm install
```

<Step>Start the local Trino cluster</Step>

The project uses minitrino to provision a local Trino cluster with Hive, MinIO, LDAP, and OAuth2 modules:

```bash
pnpm mt:start
```

<Step>Seed test data</Step>

Generate Parquet files, upload them to MinIO, and create the corresponding Trino schemas and tables:

```bash
pnpm seed --all
```

<Step>Verify the setup</Step>

Run a quick query to confirm everything is working:

```bash
pnpm query "SELECT count(*) FROM hive.test.products"
```

</Steps>

## Minitrino

The local environment uses [minitrino](https://minitrino.readthedocs.io/) to provision a Trino cluster with all necessary modules. The configuration lives in `.minitrino/lib/` within the project root — every developer gets the same setup.

### Available Commands

| Command           | Description                                             |
| ----------------- | ------------------------------------------------------- |
| `pnpm mt:start`   | Provision and start the cluster (including MinIO proxy) |
| `pnpm mt:restart` | Restart the cluster                                     |
| `pnpm mt:stop`    | Stop the cluster (keep volumes)                         |
| `pnpm mt:clean`   | Stop and remove everything                              |

### MinIO S3 Proxy

Minitrino only exposes the MinIO Console (port 9001) by default. The `mt:start` command automatically starts a lightweight proxy that makes the S3 API available on `localhost:9000` for local tooling.

## Seeding Test Data

The seed command generates Parquet files, uploads them to MinIO, and creates the corresponding Trino schemas and tables. Each run is a full reset — existing tables and data are replaced with freshly generated records.

| Command                         | Description                         |
| ------------------------------- | ----------------------------------- |
| `pnpm seed --all`               | Seed all definitions                |
| `pnpm seed -d <name>`           | Seed a specific definition          |
| `pnpm seed -d <name> -d <name>` | Seed multiple definitions           |
| `pnpm seed --all --amount 500`  | Custom record count (default: 1000) |

### Adding a Dataset

Seed definitions are configured in `tooling/test-data/seed.config.ts`. To add a custom dataset, define `columns` and `generate` inline or create a new file under `tooling/test-data/src/datasets/`:

```ts
import type { ColumnDefinition } from "../seed/config"

export const myColumns: ColumnDefinition[] = [
  { name: "id", type: "BIGINT" },
  { name: "value", type: "VARCHAR" },
]

export async function myGenerate(
  amount: number,
  targetDir: string
): Promise<string> {
  // Generate parquet file, return path
}
```

Then import and register the dataset in `tooling/test-data/seed.config.ts`.

## Querying Trino

A lightweight query tool is included for quick verification:

```bash
# Table output (default)
pnpm query "SELECT * FROM hive.test.products LIMIT 5"

# JSON output
pnpm query "SELECT * FROM hive.test.orders LIMIT 3" -f json

# CSV output
pnpm query "SELECT count(*) FROM hive.test.products" -f csv
```

## Connection Details

| Service | URL | Credentials |
| --- | --- | --- |
| Trino | `http://localhost:8080` | user: `admin`, no password |
| Trino UI | `https://localhost:8443/ui` | `admin@minitrino.com` |
| MinIO Console | `http://localhost:9001` | `access-key` / `secret-key` |
| MinIO S3 API | `http://localhost:9000` (via proxy) | `access-key` / `secret-key` |

<Note>
  The Trino UI requires `https://` since the setup uses OAuth2. Your browser may
  show a certificate warning that you need to bypass.
</Note>

## Default Users

## Troubleshooting

### Seed fails with "bucket does not exist"

Ensure the MinIO proxy is running. It starts automatically with `pnpm mt:start`, but you can restart it manually:

```bash
pnpm mt:proxy
```

### Seed fails with "401 Unauthorized"

Trino uses user-only auth (no password) for local development. This works out of the box with minitrino defaults. Verify the cluster is running with `pnpm mt:start`.

### Query fails with connection error

Make sure minitrino is running:

```bash
pnpm mt:start
```
