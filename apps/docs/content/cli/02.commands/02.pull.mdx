Run `pull` to introspect a remote table and generate its typed endpoint files. It writes the interface, query schema, config, and JSON schema. Run it with no options and it prompts for the source, catalog, schema, and table.

<Command variant="exec">lakeql-cli pull</Command>

Pass those values as options to skip the prompts:

<Command variant="exec">
  lakeql-cli pull --source warehouse --catalog hive --schema sales --table
  orders
</Command>

Generated files land under your configured source path, organized by data source, catalog, and schema. See [Key Concepts](/docs/lakeql/introduction/key-concepts) for the layout. To generate many endpoints at once, use `--bulk` with a bulk config.

## Bulk pull

`pull --bulk` reads a bulk config (`import.config.mjs` by default, generated by [`generate-import-config`](/docs/cli/commands/generate-import-config)) and pulls every entry. Each entry may name the `dataSource` it belongs to:

<Command variant="exec">lakeql-cli pull --bulk</Command>

- **Without `--source`**, every entry is processed and each is resolved against its own `dataSource`. A multi-source config pulls from all of its sources in one run; each distinct source is connected once and closed at the end.
- **With `--source &lt;value&gt;`**, `--source` acts as a filter: only entries whose `dataSource` matches are pulled (the others are skipped).

In a **single-source project** (exactly one data source configured) you may omit `dataSource` on each entry — it defaults to the sole source. In a **multi-source project**, `dataSource` is required per entry; an entry that omits it when more than one source is configured (and no `--source` filter pins one) is a configuration error.

<Note>
  `pull` always generates a read-only endpoint (`mutation: false`). It does not
  add a `Mutation` root field or otherwise make the endpoint writable. To enable
  writes, add a `mutation` block to the generated `endpoint.json` and
  regenerate. See [Mutations](/docs/lakeql/endpoints/mutations).
</Note>

<Warning>
  `pull` recreates the endpoint's output directory. It recursively deletes the
  target table's generated folder before writing. Do not keep hand-edited files
  inside a generated endpoint directory. Put customizations in your own modules.
</Warning>

<Note>
  `pull` updates the config registry by default, so new endpoints are type-safe.
  Pass `--skip-registry` to skip that step, then run
  [`create-registry`](/docs/cli/commands/create-registry) later.
</Note>
