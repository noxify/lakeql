title: "lakeql-cli pull --bulk"
navTitle: "bulk-pull"

The bulk pull mode allows you to define all tables and views to pull in a single config file and process them in one command. Each schema entry runs in parallel for faster execution.

## Syntax

```bash
lakeql-cli pull --bulk [options]
```

## Options

| Flag                   | Type    | Required | Default              | Description                         |
| ---------------------- | ------- | -------- | -------------------- | ----------------------------------- |
| `--bulk`               | boolean | Yes      | —                    | Enables bulk mode                   |
| `--bulk-config <path>` | string  | No       | `import.config.mjs`  | Path to the bulk import config file |
| `--catalog <catalog>`  | string  | No       | `HIVE_CATALOG` env   | Global catalog override             |
| `--skip-registry`      | boolean | No       | `false`              | Skip config registry generation     |
| `--source-path <path>` | string  | No       | Invocation directory | Base path for generated code        |

## Config file

The config file is an ES module (`.mjs`) that exports an array of pull entries. Use the `@type` JSDoc annotation for type-safety and autocomplete:

```javascript
// import.config.mjs

/** @type {import('@lakeql/cli').BulkPullConfig} */
export default [
  {
    schema: "sales",
    tables: ["orders", "customers", "products"],
    views: ["daily_revenue"],
  },
  {
    schema: "analytics",
    tables: ["events", "sessions"],
  },
  {
    schema: "inventory",
    catalog: "warehouse", // optional catalog override per entry
    tables: ["stock_levels"],
    views: ["low_stock_alerts"],
  },
]
```

## Config schema

Each entry in the array has the following shape:

| Field     | Type       | Required | Description                     |
| --------- | ---------- | -------- | ------------------------------- |
| `schema`  | `string`   | Yes      | The schema to pull from         |
| `catalog` | `string`   | No       | Catalog override for this entry |
| `tables`  | `string[]` | No       | List of tables to pull          |
| `views`   | `string[]` | No       | List of views to pull           |

At least one of `tables` or `views` should be provided per entry.

## Catalog precedence

The catalog is resolved in the following order (first match wins):

1. `--catalog` CLI flag (highest priority)
2. `catalog` field in the config entry
3. `HIVE_CATALOG` environment variable (fallback)

## Execution behavior

- All schema entries are processed **in parallel** for faster execution.
- Tables and views within a single entry are processed sequentially.
- The config registry is generated **once** at the end (not per entry).
- If one entry fails, the remaining entries continue to execute.
- Progress is displayed using a structured task list in the terminal.

## Usage

```bash
# Using default config file (import.config.mjs)
lakeql-cli pull --bulk

# Using a custom config file
lakeql-cli pull --bulk --bulk-config=./my-import.config.mjs

# With global catalog override
lakeql-cli pull --bulk --catalog my_catalog

# Skip registry generation
lakeql-cli pull --bulk --skip-registry
```

## Terminal output

```
⠋ Pull data
  ✓ hive/sales — 4 item(s) pulled
  ⠋ hive/analytics — 2 item(s)
    → Pulling 2 table(s)...
  ✓ warehouse/inventory — 2 item(s) pulled
✓ Pull data
✓ Create registry
```

## Type export

The `BulkPullConfig` and `BulkPullEntry` types are exported from `@lakeql/cli` for use in your config file:

```typescript
import type { BulkPullConfig, BulkPullEntry } from "@lakeql/cli"
```
