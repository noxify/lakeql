The CLI needs the same environment your `lakeql.config.ts` references — data source hosts, credentials, and so on — because it connects to the data source to introspect and generate.

## Loading an Env File

Every command accepts the global `--env [path]` option. It loads an env file into the environment **before** the config is read, so a config that references `env.*` resolves its values:

<Command variant="exec">lakeql-cli pull --env .env</Command>

- Given without a value, `--env` defaults to `.env`.
- Relative paths resolve against the directory you ran the command from.
- Loading uses Node's built-in `.env` parser — no extra dependency.
- A missing or unreadable file is a hard error, since you asked for it explicitly. Omit `--env` to use the ambient environment instead.

## CLI Log Level

The CLI's own verbosity is controlled by `LOG_LEVEL`, one of `debug`, `info`, `warn`, or `error`. It defaults to `warn`.

```bash
LOG_LEVEL=debug lakeql-cli pull --env .env
```
