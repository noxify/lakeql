The CLI reads the project's `lakeql.config.ts` — the same config the server uses — through [`@lakeql/config`](/docs/packages/config). There is no CLI-specific config file; the data sources, adapters, and source path all come from `lakeql.config.ts`.

```ts
import { defineConfig } from "@lakeql/config"
import { trinoAdapterDefinition } from "@lakeql/adapter-trino"

export default defineConfig({
  sourcePath: "src",
  adapters: [trinoAdapterDefinition],
  dataSources: {
    warehouse: {
      adapter: "trino",
      connection: {/* ... */},
    },
  },
})
```

## What the CLI Uses

- **`dataSources`** — introspection and generation commands target a source by name (the `--source` option), or prompt you to pick one.
- **`sourcePath`** — the base path under which generated files are written; commands can override it with `--source-path`.

## Loading Order

The CLI loads any [`--env`](/docs/cli/configuration/environment-variables) file first, then reads `lakeql.config.ts`, so a config that reads `env.*` sees the loaded values. The loaded config is cached for the duration of a command.

<Note>
  Create the config file with [`init`](/docs/cli/commands/init), or get one
  pre-populated by scaffolding with [create-app](/docs/lakeql/create-app). See
  [Configuration](/docs/lakeql/configuration) for the full config file
  reference.
</Note>
