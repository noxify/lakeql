title: Storage Operations
navTitle: Storage Operations
description: Upload, list, and delete operations against object storage.
---

Storage operations are the narrow interface the external-storage write strategy uses to talk to object storage. They have a single responsibility — moving files in and out of storage — and deliberately know nothing about load strategies or partitioning.

## Responsibilities

- **Upload** — write a serialized file to a storage path.
- **List** — enumerate files under a prefix.
- **Delete** — remove files, used during cleanup.

Load-strategy semantics (whether to replace, append, or extend) live in the [write strategy](/docs/data-sources/write-pipeline/execute-write-pipeline), not here. The [table manager](/docs/data-sources/write-pipeline/execute-write-pipeline) handles the external-table DDL that registers uploaded files. This separation keeps each piece testable on its own and lets a write strategy swap the storage backend without touching its load logic.

<Note>
  Storage is only involved in the external-storage write path. The INSERT
  strategy writes through SQL and does not touch object storage.
</Note>
