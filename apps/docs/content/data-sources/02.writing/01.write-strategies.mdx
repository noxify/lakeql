A write runs through the strategy configured for the data source. Each strategy takes the records to write plus a load strategy. The `write()` call resolves with no value — it either completes or throws.

## External Storage

```text
records
  → serializer        (records → a file format)
  → storage upload    (write the file to object storage)
  → table manager     (register/update the table via DDL)
  → cleanup           (according to the load strategy)
```

This path requires a serializer, [storage operations](/docs/data-sources/storage), and a table manager. It suits engines backed by object storage with an external table catalog. A write call without a resolvable `basePath` throws.

## INSERT INTO

```text
records
  → schema mapper
  → batched statements
  → data source query (INSERT INTO)
  → optional staging + swap
```

This path runs entirely through SQL and does not depend on object storage.

## Trino, today the only write-capable adapter

Trino implements both paths above, selected by its `writeConfig`. See [Trino write config](/docs/data-sources/trino/write-config) for the two concrete shapes side by side — this page covers the mechanics every write-capable adapter shares, not any one adapter's config format.

## Write Capability by Adapter

| Adapter | External storage       | INSERT INTO            |
| ------- | ---------------------- | ---------------------- |
| Trino   | Yes                    | Yes                    |
| Fabric  | No — read-only adapter | No — read-only adapter |

A future write-capable adapter adds a row here, plus its own `<adapter>/write-config.mdx` page for the concrete shape — it does not need a new section.

## Responsibility Boundaries

Each part has a narrow job: the **data source** executes SQL and exposes DDL; the **write strategy** owns load-strategy semantics, batching, staging, and rollback; the **serializer** converts records to a format; **storage operations** handle upload, list, and delete without knowing load strategies; the **table manager** handles external-table DDL only for strategies that need it.
