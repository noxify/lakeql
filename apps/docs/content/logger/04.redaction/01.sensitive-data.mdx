---
title: Sensitive Data
description: How @lakeql/logger automatically redacts passwords, tokens, and other sensitive fields from log output.
---

The logger automatically redacts sensitive data from context and metadata objects before writing to the transport. This prevents accidental exposure of credentials, tokens, and other secrets in log files and console output.

## How it works

Redaction is applied at two levels:

1. **LogLayer plugin** — `@loglayer/plugin-redaction` intercepts log data before it reaches the transport
2. **Format-level redaction** — `fast-redact` processes context objects in the winston formatter for development output

Both use the same path configuration, ensuring consistent redaction regardless of output format.

## Redacted paths

The following wildcard paths are redacted by default:

```typescript
const redactPaths = [
  "*.password",
  "*.username",
  "*.secret",
  "*.token",
  "*.key",
  "*.credentials",
  "*.headers.*",
]
```

Any object property matching these paths — at any nesting depth — will have its value replaced with `[REDACTED]` in the output.

## Example

```typescript
import { createLogger } from "@lakeql/logger"

const logger = createLogger()

logger
  .withContext({
    user: {
      name: "alice",
      password: "super-secret-123",
      token: "Bearer eyJhbG...",
    },
  })
  .info("User authenticated")

// Output:
// [2024-01-15T10:30:00.000Z] INFO - User authenticated
// Context: { user: { name: 'alice', password: '[REDACTED]', token: '[REDACTED]' } }
```

## Error serialization

Errors are serialized using `serialize-error` before logging. This converts Error objects (with non-enumerable properties like `stack` and `message`) into plain objects that can be properly formatted and redacted.

```typescript
try {
  await connectToDatabase()
} catch (err) {
  logger.error("Connection failed", err as Error)
  // Stack trace, message, and name are all included in the output
  // Any sensitive fields in the error object are redacted
}
```
