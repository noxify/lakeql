## Available levels

The logger supports four levels, in order from most to least severe:

| Level   | Use Case                                           |
| ------- | -------------------------------------------------- |
| `error` | Unrecoverable failures, exceptions                 |
| `warn`  | Unexpected situations that don't block execution   |
| `info`  | Key operational events (server start, connections) |
| `debug` | Detailed diagnostic information                    |

Messages are only output when their level is equal to or more severe than the configured level. For example, with `LOG_LEVEL=warn`, only `error` and `warn` messages appear.

## Configuration

### LOG_LEVEL

Controls the minimum log level. Set via environment variable:

```bash
# Show all messages including debug
LOG_LEVEL=debug

# Only errors and warnings (default)
LOG_LEVEL=warn

# Errors only
LOG_LEVEL=error
```

The default is `warn` when not specified.

### Validation

The environment variable is validated at startup using `@t3-oss/env-core` with Zod. Invalid values cause a startup error with a clear message about allowed options.

```typescript
// Accepted values
type LogLevel = "error" | "warn" | "info" | "debug"
```

### CI and lint environments

Environment validation is skipped when `CI=true` or during lint operations (`npm_lifecycle_event === "lint"`) to prevent false failures in automated environments.
