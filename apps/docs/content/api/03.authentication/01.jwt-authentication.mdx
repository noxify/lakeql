Authentication starts with a `tokenResolver`: a function that inspects the incoming request, validates its token, and returns the decoded payload (the current user) or `null` when unauthenticated.

```ts
import type { TokenResolver } from "@lakeql/config"
import { createRemoteJWKSet, jwtVerify } from "jose"

const JWKS = createRemoteJWKSet(
  new URL(`https://login.microsoftonline.com/${tenantId}/discovery/v2.0/keys`)
)

export const tokenResolver: TokenResolver = async (request) => {
  const authHeader = request.headers.get("authorization")
  if (!authHeader?.startsWith("Bearer ")) {
    return null
  }

  const token = authHeader.slice(7)
  try {
    const { payload } = await jwtVerify(token, JWKS, {
      audience: clientId,
      issuer: `https://login.microsoftonline.com/${tenantId}/v2.0`,
    })
    return { ...payload, __rawToken: token }
  } catch {
    return null
  }
}
```

Pass it to the server via [`defineApiConfig`](/docs/api/server-setup/define-config):

```ts
defineApiConfig({ runtime, tokenResolver })
```

## Identity Resolution

The decoded payload is mapped to a `ResolvedIdentity` by the `identityResolver`, which defaults to the Entra ID resolver ([`entraIdIdentityResolver`](/docs/api/api-reference#entra-id-identity-resolver)). The resolved identity drives permission checks and tells LakeQL whether the caller is a service principal. Override `identityResolver` for other identity providers.

<Note>
  Returning `null` from the token resolver leaves the request unauthenticated.
  Whether that is allowed depends on the permissions and resolvers you configure
  — an unauthenticated request resolves to the system user with no
  request-scoped credentials.
</Note>
