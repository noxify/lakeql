---

Pass your runtime config to [`defineApiConfig`](/docs/api/api-reference#define-api-config). It returns a resolved config with convenience methods. Call `startServer()` to run the full HTTP server.

```ts
import { defineApiConfig } from "@lakeql/api/config"

const server = defineApiConfig({
  runtime,
  tokenResolver,
  // Declared in lakeql.config.ts under `auth.permissions` and forwarded here.
  permissions: project.config.auth?.permissions ?? [],
  baseDir: import.meta.dirname,
  schemaPath: "./schemas",
})

await server.startServer()
```

## The Runtime

The API server does not build the runtime. Your application builds it with [`createLakeQLRuntime`](/docs/packages/config/api-reference#create-lake-ql-runtime) and passes it in as `runtime`. Resolvers reach read strategies through it. This keeps the API out of the runtime lifecycle, so your code owns shutdown.

## Graceful Shutdown

Because the application owns the runtime, close it on shutdown signals:

```ts
const shutdown = async () => {
  await runtime.close()
  process.exit(0)
}
process.on("SIGTERM", shutdown)
process.on("SIGINT", shutdown)
```

## Lower-Level Entry Points

Need the Yoga instance without starting an HTTP listener? `defineApiConfig` also exposes `createYogaServer(logger)`. For direct use, the package exports [`createApiServer`](/docs/api/api-reference#create-api-server) and [`startApiServer`](/docs/api/api-reference#start-api-server).
