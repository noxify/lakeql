[`defineApiConfig`](/docs/api/api-reference#define-api-config) takes the runtime config and returns a resolved config with convenience methods. Call `startServer()` to run the full HTTP server.

```ts
import { defineApiConfig } from "@lakeql/api/config"

const server = defineApiConfig({
  runtime,
  tokenResolver,
  permissions,
  baseDir: import.meta.dirname,
  schemaPath: "./schemas",
})

await server.startServer()
```

## The Runtime

The API server does not build the runtime — the application does, with [`createLakeQLRuntime`](/docs/packages/config/api-reference#create-lake-ql-runtime), and passes it in as `runtime`. Resolvers reach read strategies through it. This keeps the API out of the runtime lifecycle; your code owns shutdown.

## Graceful Shutdown

Because the application owns the runtime, close it on shutdown signals:

```ts
const shutdown = async () => {
  await runtime.close()
  process.exit(0)
}
process.on("SIGTERM", shutdown)
process.on("SIGINT", shutdown)
```

## Lower-Level Entry Points

`defineApiConfig` also exposes `createYogaServer(logger)` if you need the Yoga instance without starting an HTTP listener. The package additionally exports [`createApiServer`](/docs/api/api-reference#create-api-server) and [`startApiServer`](/docs/api/api-reference#start-api-server) for direct use.
