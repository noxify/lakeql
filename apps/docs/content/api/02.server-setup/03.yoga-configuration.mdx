LakeQL's server runs on [GraphQL Yoga](https://the-guild.dev/graphql/yoga-server). The `yogaConfig` option passes overrides and plugins straight through. You tune the underlying Yoga instance, and the API package stays independent of your additions.

```ts
const server = defineApiConfig({
  runtime,
  tokenResolver,
  yogaConfig: {
    // Yoga options and plugins
    plugins: [myPlugin],
  },
})
```

Use this for Yoga-level concerns like additional envelope plugins or GraphiQL settings. CORS is **not** configured here. It is a dedicated [`cors`](/docs/api/customization/cors-configuration) option applied by the Hono layer. To forward execution errors to telemetry, prefer the dedicated [`onError`](/docs/api/customization/error-handling) hook over a plugin.

<Note>
  `yogaConfig` is applied on top of LakeQL's own Yoga setup. Plugins you add run
  alongside the built-in ones, including the error-logging plugin.
</Note>

## Built-In Defaults

Two Yoga defaults are worth knowing. GraphQL errors are masked (`maskedErrors: true`). GraphiQL is served only when `NODE_ENV` is `development`. Override either through `yogaConfig`.
