LakeQL's server is built on [GraphQL Yoga](https://the-guild.dev/graphql/yoga-server). The `yogaConfig` option passes overrides and plugins straight through, so you can tune the underlying Yoga instance without the API package depending on your additions.

```ts
const server = defineApiConfig({
  runtime,
  tokenResolver,
  yogaConfig: {
    // Yoga options and plugins
    plugins: [myPlugin],
  },
})
```

Use this for Yoga-level concerns — additional envelope plugins, GraphiQL settings, and so on. CORS is **not** configured here; it is a dedicated [`cors`](/docs/api/customization/cors-configuration) option applied by the Hono layer. For forwarding execution errors to telemetry, prefer the dedicated [`onError`](/docs/api/customization/error-handling) hook over a plugin.

<Note>
  `yogaConfig` is applied on top of LakeQL's own Yoga setup. Plugins you add run
  alongside the built-in ones, including the error-logging plugin.
</Note>

## Built-In Defaults

A few Yoga defaults are worth knowing: GraphQL errors are masked (`maskedErrors: true`), and GraphiQL is served only when `NODE_ENV` is `development`. Both can be overridden through `yogaConfig`.
