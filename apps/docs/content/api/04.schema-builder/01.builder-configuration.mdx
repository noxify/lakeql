LakeQL exports a configured Pothos [`builder`](/docs/api/api-reference#builder) that the generated query schemas build on. Configuring it in one place keeps auth, validation, scalars, and pagination consistent across every endpoint.

## Plugins

The builder enables two Pothos plugins:

- **scope-auth** — enforces the `authorized`, `readPermission`, and `writePermission` scopes on every field. See [scope authorization](/docs/api/authentication/scope-authorization).
- **validation** — validates input arguments with Zod schemas. See [input validation](/docs/api/schema-builder/input-validation).

## Registered Types

On top of the plugins, the builder registers the [scalar types](/docs/api/schema-builder/scalar-types), the [comparison input types](/docs/api/schema-builder/comparison-types), the `SortDirection` enum, and the [pagination types](/docs/api/schema-builder/pagination).

## Max Records Per Page

The builder reads a maximum page size from the environment, overridable at runtime with [`setMaxRecordsPerPage`](/docs/api/api-reference#set-max-records-per-page). `defineApiConfig`'s `maxRecordsPerPage` option (default `2000`) drives this. The `perPage` paging argument is validated against it.
