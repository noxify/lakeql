Beyond the auto-generated query schemas from the CLI, you can add custom GraphQL queries and mutations by creating additional schema files. The server discovers them automatically via glob patterns during startup.

## File discovery

The schema loader scans for files matching these patterns in the configured `schemaPath` directory:

```
schemas/**/query-schema.{ts,js,mjs}
schemas/**/mutation-schema.{ts,js,mjs}
**/query-schema.{ts,js,mjs}
**/mutation-schema.{ts,js,mjs}
```

Any file named `query-schema.ts` or `mutation-schema.ts` (or `.js`/`.mjs`) that imports and uses the shared builder will have its types registered in the final schema.

## Creating a custom query

Create a file in your schema directory:

```ts shouldAnalyze path="src/schemas/custom/query-schema.ts"
import { builder } from "@lakeql/api/builder"

builder.queryField("serverInfo", (t) =>
  t.field({
    type: "String",
    description: "Returns the current server version",
    resolve: () => "1.0.0",
  })
)
```

## Creating a custom mutation

To add mutations, first ensure the mutation type is registered, then add your field:

```ts shouldAnalyze path="src/schemas/custom-mutations/query-schema.ts"
import { builder } from "@lakeql/api/builder"

// Register mutation type if not already done
builder.mutationType({})

builder.mutationField("refreshCache", (t) =>
  t.field({
    type: "Boolean",
    description: "Invalidates the internal cache",
    authScopes: {
      authorized: true,
    },
    resolve: async (_parent, _args, context) => {
      context.logger.info(
        "Cache refresh triggered by",
        context.currentUser?.userName
      )
      // perform cache invalidation
      return true
    },
  })
)
```

## Custom types with arguments

```ts shouldAnalyze path="src/schemas/analytics/query-schema.ts"
import { builder } from "@lakeql/api/builder"

const MetricResult = builder
  .objectRef<{
    name: string
    value: number
    timestamp: Date
  }>("MetricResult")
  .implement({
    fields: (t) => ({
      name: t.exposeString("name"),
      value: t.exposeFloat("value"),
      timestamp: t.expose("timestamp", { type: "DateTime" }),
    }),
  })

builder.queryField("metrics", (t) =>
  t.field({
    type: [MetricResult],
    args: {
      name: t.arg.string({ required: true }),
      from: t.arg({ type: "DateTime", required: true }),
      to: t.arg({ type: "DateTime", required: true }),
    },
    authScopes: {
      readPermission: {
        catalog: "hive",
        schema: "analytics",
        tableName: "metrics",
      },
    },
    resolve: async (_parent, args, context) => {
      // Query Trino for metrics data
      return []
    },
  })
)
```

## Directory structure example

```
src/schemas/
├── generated/                    # Auto-generated by `lakeql-cli pull`
│   └── hive/
│       └── sales/
│           ├── users/
│           │   ├── query-schema.ts
│           │   └── mutation-schema.ts
│           └── orders/
│               ├── query-schema.ts
│               └── mutation-schema.ts
├── custom/                       # Auto-generated by `lakeql-cli create-endpoint`
│   └── analytics/
│       └── tracking/
│           └── user_events/
│               ├── query-schema.ts
│               └── mutation-schema.ts
├── manual/                       # Your hand-written custom schemas
│   └── query-schema.ts
└── analytics/
    └── query-schema.ts
```
