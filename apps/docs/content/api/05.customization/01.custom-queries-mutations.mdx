The generated endpoints attach to the shared [`builder`](/docs/api/api-reference#builder). You add custom queries and mutations the same way — define fields on the builder, and they join the schema the server serves.

```ts
import { builder } from "@lakeql/api/builder"

builder.queryField("ping", (t) =>
  t.string({
    resolve: () => "pong",
  })
)
```

Because it is the same builder, your custom fields get the same facilities as the generated ones: the scope-auth scopes, the validation plugin, and the registered scalar and comparison types.

## Two Prerequisites

Custom fields do not reach the served schema by themselves:

1. **Import your module before `startServer()`.** The server discovers schema modules by globbing the generated `query-schema`/`mutation-schema` files under its schema path — it does not import arbitrary files. A module like `src/custom-fields.ts` is only included if your entry point imports it before starting the server (or you name it to match the glob).

   ```ts
   import "./custom-fields" // registers the builder fields
   await server.startServer()
   ```

2. **The `Mutation` root type exists only when a generated `mutation-schema` file is present.** If your project has no generated mutations, `builder.mutationField(...)` has no `Mutation` type to attach to and Pothos throws "Mutation type not defined". Add a generated mutation first, or register the mutation type yourself.

## Authorization

Declare the scopes a custom field requires through Pothos's `authScopes` field option — for example, require an authenticated user, or a read permission on a particular table. See [scope authorization](/docs/api/authentication/scope-authorization).

## Validation

Attach a Zod schema to an argument via its `validate` option to validate input before the resolver runs. See [input validation](/docs/api/schema-builder/input-validation).

## Accessing Data

Resolvers reach the runtime through the GraphQL context, which exposes `getReadStrategy(name)` and `getWriteStrategy(name)` — there is no `context.runtime`.

```ts
builder.queryField("orderCount", (t) =>
  t.int({
    resolve: async (_root, _args, context) => {
      const strategy = context.getReadStrategy("warehouse")
      // use the strategy to read, the same path generated resolvers take
      // ...
      return count
    },
  })
)
```
