`@lakeql/api` sits at the top of the stack. It does not own the runtime or the data sources — the application composes those with [`@lakeql/config`](/docs/packages/config) and passes the runtime in. The API package is responsible for the GraphQL surface: schema, request handling, and HTTP serving.

## What It Does

- **Schema composition** — builds a GraphQL schema from the generated endpoint files under your schema path.
- **Authentication** — resolves a token into a current user and identity.
- **Authorization** — checks per-table read/write permissions before a query runs.
- **Execution** — runs the query through the runtime's read strategy for the target data source.
- **Serving** — exposes the GraphQL endpoint and a health check over HTTP, built on GraphQL Yoga.

## Subpath Exports

The package publishes subpath exports rather than a single root. You import each piece from its module — for example:

```ts
import { defineApiConfig } from "@lakeql/api/config"
import { createApiResolveAuth } from "@lakeql/api/resolve-auth"
import { trinoUserImpersonation } from "@lakeql/api/trino-user-impersonation"
```

The [API reference](/docs/api/api-reference) lists every export; each lives under the subpath matching its source module.
