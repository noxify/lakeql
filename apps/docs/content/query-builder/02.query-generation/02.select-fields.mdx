---
title: Select Fields
description: How selectFields, transformFields, and dateFields control the SELECT clause.
---

## selectFields

The `selectFields` array determines which columns appear in the `records` CTE's SELECT clause. Each entry is a string matching a column name or a Kysely select expression.

```typescript
const compiled = generateQuery<MyTable>({
  // ...
  selectFields: ["id", "name", "email", "created_at"],
})
```

Only the fields listed here are included in the query output. This keeps the generated SQL lean — matching exactly what the GraphQL client requested.

## transformFields

When a GraphQL field name differs from the underlying database column, `transformFields` provides the mapping. Keys are the GraphQL names; values are the actual column names in the database.

```typescript
const compiled = generateQuery<MyTable>({
  // ...
  selectFields: ["customerName", "orderDate"],
  transformFields: {
    customerName: "customer_name",
    orderDate: "order_date",
  },
})
```

In the generated SQL, the query selects `"customer_name" as "customer_name"` using the database column, while the rest of the system references the GraphQL name. Transform fields are also respected during filtering and sorting.

## dateFields

Fields listed in `dateFields` are automatically wrapped in Trino's `to_unixtime()` function. This converts timestamp values to Unix epoch seconds for consistent serialization in GraphQL responses.

```typescript
const compiled = generateQuery<MyTable>({
  // ...
  selectFields: ["id", "created_at", "updated_at"],
  dateFields: ["created_at", "updated_at"],
})
```

The generated SQL for a date field looks like:

```sql
SELECT to_unixtime(created_at) AS "created_at"
```

If a date field also has a `transformFields` mapping, the transform is applied inside the `to_unixtime()` call:

```sql
SELECT to_unixtime(order_date) AS "order_date"
```
