## Simple columns

Basic scalar types map directly to their JavaScript equivalents:

```typescript
import { parseColumns } from "@lakeql/column-parser"

const columns = [
  { name: "username", type: "varchar", extra: "", description: "User name" },
  { name: "age", type: "integer", extra: "", description: "User age" },
  { name: "active", type: "boolean", extra: "", description: "Is active" },
  { name: "score", type: "double", extra: "", description: "User score" },
]

const result = parseColumns(columns)
// {
//   username: { type: "string" },
//   age: { type: "number" },
//   active: { type: "boolean" },
//   score: { type: "number" }
// }
```

## Date types

Date and timestamp types are recognized as temporal values:

```typescript
import { parseColumns } from "@lakeql/column-parser"

const columns = [
  { name: "created_at", type: "date", extra: "", description: "Creation date" },
  {
    name: "updated_at",
    type: "timestamp",
    extra: "",
    description: "Last update",
  },
]

const result = parseColumns(columns)
// {
//   created_at: { type: "Date" },
//   updated_at: { type: "DateTime" }
// }
```

## Complex types

Arrays, maps, and row types are recursively parsed into nested structures:

```typescript
import { parseColumns } from "@lakeql/column-parser"

const columns = [
  { name: "tags", type: "array(varchar)", extra: "", description: "Tags list" },
  {
    name: "address",
    type: "row(street varchar, city varchar, zip integer)",
    extra: "",
    description: "Address",
  },
  {
    name: "contacts",
    type: "array(row(name varchar, phone varchar))",
    extra: "",
    description: "Contact list",
  },
]

const result = parseColumns(columns)
// {
//   tags: { type: "array", items: { type: "string" } },
//   address: {
//     type: "object",
//     properties: {
//       street: { type: "string" },
//       city: { type: "string" },
//       zip: { type: "number" }
//     }
//   },
//   contacts: {
//     type: "array",
//     items: {
//       type: "object",
//       properties: {
//         name: { type: "string" },
//         phone: { type: "string" }
//       }
//     }
//   }
// }
```

## Full pipeline example

In practice, column metadata comes from querying Trino's `information_schema` and is passed through the column parser before being used by the file generator:

```typescript
import { parseColumns } from "@lakeql/column-parser"

// Simulating Trino DESCRIBE output
const trinoColumns = [
  { name: "id", type: "bigint", extra: "", description: "" },
  { name: "email", type: "varchar", extra: "", description: "User email" },
  { name: "is_verified", type: "boolean", extra: "", description: "" },
  {
    name: "preferences",
    type: "row(theme varchar, notifications boolean)",
    extra: "",
    description: "User preferences",
  },
]

const parsedFields = parseColumns(trinoColumns)
// parsedFields is now ready for schema-generator or file-generator
```
