### Redesigned partitioning controls and a derived load_timestamp field

The mutation form's partitioning control is now a rich three-option picker — Off, By write timestamp, and By field / custom format — with a title and description per option. A freshly enabled mutation now starts with partitioning **off** rather than by write timestamp, so nothing is imposed on the author; switching to timestamp or field mode is a deliberate choice.

In timestamp mode the editor automatically materializes a managed `load_timestamp` `DateTime` field: it appears as a read-only row in the Fields list and is appended to the exported definition, while the CLI/runtime remains responsible for filling its value. It is never stored as an editable field, so leaving timestamp mode removes it with no undo/redo entry. If a field named `load_timestamp` already exists, the timestamp mode is disabled so export never produces a duplicate.

The "By field / custom format" mode replaces the free-text input with a combobox over your top-level fields (date and datetime fields expand into year/month/day/hour/minute/second components). Chosen segments render as reorderable, removable badges whose order is the exported partition path, and the assembled string is validated live.

Note: because timestamp mode is the effective default for a definition that omits `partitioning`, exporting such a definition from the studio now adds a `load_timestamp` field to its fields — the intended behavior of this feature.
