### Fix invalid validations added when switching fields

Opening the "Add validation" picker on one field and then selecting another field no longer adds an empty, invalid validation to the newly selected field. Previously each switch added another one, so the "Invalid input" issues piled up.

### Confirm the write-timestamp field with a toast

Clicking "Add write-timestamp field" now shows a success toast with a "Show field" action that opens the Fields view with the new field selected. The hint below the disabled button no longer reads like an error once the field has been added; the collision message only appears when an ordinary field already uses the name.

### Prefill partitioning from the write-timestamp field

When "By fields" is selected and no partition fields are chosen yet, "Add write-timestamp field" also sets the partition path to the new field's year, month, and day. An existing partition path or the "Off" mode is left unchanged, and a single undo reverts both the field and the partitioning.

### Readable issue count on the desktop rail

On desktop, the issue count on the Validations rail icon is now a filled red counter on the icon's top-right corner instead of red text drawn over the icon. Counts above 99 show as "99+". The mobile navigation sheet is unchanged.

### Flag partition fields that do not exist

A partition segment that names no field, or a name shared by several fields, is now reported as a validation issue and blocks export. This typically happens when importing an `endpoint.json` whose `partitioning` refers to a field that is not in `fields`. Previously such a definition passed validation and was exported unchanged. Blocked exports now also list the auto-fill and partitioning issues in their error messages.

### Jump to the partition picker from a partitioning issue

Partitioning issues in the Validations list are now clickable: they switch to the Settings view and focus the partition field picker. The picker itself shows the error state and the message when a partition segment names a field that does not exist, matches several fields, or references a derived column.

### Highlight empty required settings

The Table name, Catalog, and Schema inputs in General Settings now show an error state and an "is required" message while they are empty, matching the issue count in the header. Previously an empty input looked valid even though it blocked export.

### Clearer error for an empty partition selection

With "By fields" selected and no partition field chosen, the partition picker now shows an error state and the message "Choose at least one partition field, or set partitioning to "Off"." The Validations list reports this as one issue instead of two raw validator messages.
