### Add the `fabric-obo` feature template

`@lakeql/scaffold` ships its first feature template, `fabric-obo`, exported as `fabricOboTemplate` and registered in `featureRegistry`. It adds the Fabric On-Behalf-Of (OBO) impersonation flow to an existing project:

- requires the Fabric adapter (`@lakeql/adapter-fabric`) as a project dependency (`checkPreconditions` reads `package.json` and throws otherwise, so nothing is written) — the template never loads or executes the project config;
- contributes the `@azure/identity` dependency (pinned), the `OBO_*` env vars and schema entries (default scope `https://database.windows.net/.default`), and a static `src/fabric-impersonation-resolver.ts` exporting `fabricImpersonationResolver`. The adapter-prefixed file and export let a future adapter's resolver coexist without colliding;
- emits guidance for the `env.ts` schema and the `lakeql.config.ts` wiring (`impersonationResolver: fabricImpersonationResolver`), kept generic over data sources so it fits one or many Fabric sources, plus the Azure follow-up: delegated `Azure SQL Database` and `Azure Storage` `user_impersonation` permissions, consent (admin consent only when the tenant requires it), the OBO scope choice, and copying the new `.env.example` keys into `.env`.
