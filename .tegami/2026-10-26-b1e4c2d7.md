### Per-data-source paging resolution and runtime wiring

`@lakeql/config` now resolves per-data-source paging limits and threads them into read strategies. It exports the public `ResolvedPaging` type (`{ defaultPerPage: number; maxRecordsPerPage: number }`).

Data-source entries accept optional `defaultPerPage` and `maxRecordsPerPage` fields, and the config accepts a top-level `paging` object with the same fields as global defaults. Each field is resolved independently by precedence: per-source value, then global default, then the system default (`100` for `defaultPerPage`, `2000` for `maxRecordsPerPage`).

Supplied values must be positive integers, and the resolved `defaultPerPage` may not exceed the resolved `maxRecordsPerPage`; violations throw a `DataSourceConfigError` naming the source and the offending field or values.

Both `defineConfig` and `loadConfig` attach a resolved `paging` value to every data-source definition, and `createLakeQLRuntime` passes it into each adapter's `createReadStrategy`.
