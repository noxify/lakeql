### Endpoint Builder

`@lakeql/studio` is the shared UI and logic package of the LakeQL Endpoint Builder. It exports a React `EndpointBuilder` component and a precompiled stylesheet (`@lakeql/studio/styles.css`), so a consumer renders the builder without any Tailwind configuration. The package ships a library build (ESM and types) and a standalone static bundle from the same source.

The builder authors a LakeQL endpoint definition (`version: "2.0"`) over a live state that is validated continuously against the canonical endpoint schema, so an export can never be a file the CLI would reject.

- Author the table metadata, add and nest fields of every supported type, set per-field options and validations, and configure the mutation.
- See the live JSON, copy it, and import an existing `endpoint.json` to keep editing it. A rejected import changes nothing and raises an error toast that lists why.
- Export is gated on a valid definition. Work is kept across reloads through local autosave, and a degraded autosave raises a warning toast.
- The active view lives in the URL hash (`#settings`, `#fields`, `#validations`, `#json`), so reloads and shared links open the same view.

The shell has an icon rail (General Settings, Fields, Validations, JSON), a contextual secondary sidebar and a header with Import and Export. A command palette (⌘K or Ctrl-K) navigates to any view, runs Import and Export, jumps to open validations, adds a field of any type from a sub-view (Escape or "Back" returns), and resets the editor behind a confirmation. A theme toggle switches between light, dark and system.

The editor supports desktop widths only. Below 768px a "Desktop only" notice replaces it, and the editor stays mounted underneath so the draft and the undo history survive a temporary resize. Pass `desktopOnly={false}` to `EndpointBuilder` to render the responsive layout, where the rail and the secondary navigation open from header triggers.

### Fields canvas

Fields are authored on a drag-and-drop canvas with a field-type palette, nested field cards and a properties panel. Drag a type from the palette to add a field, and drag cards to reorder within a level or move them into and out of `Object` and `Array`-of-`Object` containers. Impossible drops (into a non-container, an array of arrays, or a field's own descendant) are rejected with a reason and no state change. Reordering is pointer-only. Adding a field from the palette, undo and redo (toolbar and shortcuts) and the command palette work by keyboard, and focus lands in the field's name input after a keyboard add or a jump from the Validations view. Validation changes are announced through a live region.

### Validation

The Validations view lists every current issue readably, with fields named by their nesting context. Activating an entry selects and focuses the offending field, or, for table name, catalog, schema, data source, base path and partitioning issues, switches to Settings and focuses the matching input. Field cards show an issue badge that clears as the issue is fixed. The Validations icon on the rail shows a filled counter (`99+` above 99). The Table name, Catalog and Schema inputs show an error state and "is required" while empty. An unnamed field reports only "Field name is invalid", not a duplicate as well.

### Mutation, write method and adapter

Enabling the mutation starts with partitioning off and the write method set to storage. The Write method control switches between Storage and Insert. Insert hides the base path, the partitioning controls and the write-timestamp helper, and the export omits `basePath` and `partitioning`. Switching from storage to insert asks for confirmation when it would remove a base path, partitioning or auto-fill options, lists what is lost, and applies everything as one undo step. Import reads an absent method as storage, and export always writes it.

The metadata form starts with an Adapter select. Trino is selectable; Microsoft Fabric, ClickHouse and DuckDB are listed but disabled until the editor supports them. The choice only shapes the editor and is not part of the exported definition. The fields follow in the order Data source, Catalog, Schema, Table name.

### Partitioning and auto-fill

Partitioning is either Off or By fields. With By fields, "Add partition field" opens a searchable popover that always opens above its button. Each field shows its type, and searching matches every typed word as part of a name, component or type, so "event year" finds `event → year`. A non-date field adds a bare segment that partitions by its raw value. `Date` and `DateTime` fields open a sub-page with a combined "year / month / day" option and the single components. A `Date` field only offers year, month and day, and a `DateTime` field adds hour, minute and second. Escape, or Backspace on an empty search, goes back. Chosen segments are removable, reorderable badges whose order is the exported partition path.

Segments reference fields by their stable id, so renaming a field keeps its segments attached and two fields with the same name no longer make a segment ambiguous. Segments in an imported file whose name is missing or shared are kept and written back unchanged, and they are reported as validation issues. An empty selection is reported once, with the message "Choose at least one partition field, or set partitioning to "Off"". Removing a partitioned field, or changing its type so a segment becomes invalid, asks for confirmation and names the affected segments. Confirming applies the change and removes only those segments in one undo step.

A write-timestamp column is an ordinary auto-fill field. "Add write-timestamp field" adds a real top-level `DateTime` field with `options.autoFill: "write_timestamp"` (default name `load_timestamp`, at most 58 characters) and confirms with a toast that offers "Show field". With By fields selected and no segments chosen yet, it also sets the partition path to the field's year, month and day, and a single undo reverts both. The validity gate mirrors the schema's auto-fill rules: reserved companion names, top-level `DateTime` only, an enabled `append` or `full_load_append` mutation, and no partition segment on a derived companion column. Importing a v1 definition fails with a clear "version no longer supported" message.
