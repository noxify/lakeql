### First-class auto-fill fields and a v2 endpoint schema contract

Endpoint definitions now declare auto-fill directly on a field via `options.autoFill: "write_timestamp"`. A write-timestamp auto-fill field must be a top-level `DateTime` field under an enabled `append` or `full_load_append` mutation; it is populated server-side on every write and exposed in the query type and table together with its derived `<name>_year` and `<name>_month` companion columns, while staying out of the mutation input. The schema rejects auto-fill on any other field type, on nested fields, on `full_load`, and when no mutation is enabled, caps an auto-fill field name at 58 characters so its companions stay within the field-name pattern, and rejects partition segments that reference a companion column in any form (use the primary field's `name:year` component form instead).

The endpoint schema version is now `"2.0"` (exported as `ENDPOINT_SCHEMA_VERSION`, with an `isSupportedVersion` helper); `"1.0"` definitions and the former `partitioning: true` value are no longer accepted — there is no compatibility shim. `partitioning` is now `false | string` only. New shared derivation helpers (`deriveAutoFillColumns`, `autoFillCompanionNames`, `findReservedNameCollisions`, `AUTO_FILL_WRITE_TIMESTAMP`) are re-exported from `@lakeql/schema-generator/endpoint-schema` as the single source of truth for companion names.

`@lakeql/datasource` adds an optional `autoFillFields` entry to `DataSourceWriteConfig` so adapters can forward auto-fill directives to the write pipeline.
