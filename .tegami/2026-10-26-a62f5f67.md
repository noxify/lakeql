### Remove environment-variable interpolation

`@lakeql/config` no longer performs `${VAR}` string interpolation on loaded configs. The `interpolateEnvVariables` export has been removed and `loadConfig` no longer runs an interpolation pass — it returns the resolved config directly.

The only field the interpolation pass could ever touch was `adapter` (always a literal), so this feature was effectively inert. Configs should read environment values directly in the config module (for example via a typed `env` object), which is the documented and unaffected pattern.

Prototype-pollution safety is preserved: a data source literally named `__proto__` remains an own property of the resolved `dataSources` map and does not mutate the prototype chain.

**Breaking:** remove any import of `interpolateEnvVariables` from `@lakeql/config`.
