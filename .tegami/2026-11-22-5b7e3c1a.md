### Remove the single-field partitioning mode and `partitioningFormat`

A bare partition name such as `region` now always partitions by the raw field value (`region=EU`), for every field type. The legacy single-field mode that turned a bare name into a date-based `year=/month=/day=` path is gone, together with `partitioningFormat`.

Date and DateTime fields are only valid as partition segments with a component, for example `event:year/event:month/event:day`. A bare Date/DateTime segment, or a component on a non-date field, is now rejected by `endpointDefinitionSchema` with a message that names the fix. A v2 endpoint file that still sets `mutation.partitioningFormat` fails validation (in `create-endpoint` as well) with a message explaining how to migrate.

The schema-generator drops `partitioningFormats`, `PartitioningFormat` and `MutationConfig.partitioningFormat`, and renames `validatePartitioningFormat` to `validatePartitioningString`. Storage drops `generatePartitionPath`, `groupRecordsByPartition`, `WritePipelineConfig.partitioningFormat` and the `"field"` partition mode (`PartitionMode` is `"disabled" | "custom"`, and `resolvePartitioningConfig` takes a single argument). Datasource, file-generator, CLI codegen and the Trino write strategy no longer carry `partitioningFormat`.
