### Generated query resolvers surface datasource errors

Generated query resolvers now wrap the read call in `try/catch` and route failures through `handleErrorResponse`, which maps a `DataSourceError` to a `GraphQLError` with a code and HTTP status. Previously an adapter failure (for example a Trino `PERMISSION_DENIED`) escaped the resolver and was masked by Yoga's `maskedErrors` to a generic "Unexpected error."; now it reaches the client as an explicit, classified GraphQL error. Re-run code generation to pick this up in existing projects.
