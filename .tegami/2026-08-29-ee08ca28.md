### Log GraphQL execution errors; add an onError telemetry hook

The API now logs every GraphQL execution error through the configured logger, so datasource failures stay observable in server logs even though they are returned to the client as handled `GraphQLError`s (which Yoga would otherwise not log). The level reflects the `DataSourceError` category: `network` and `timeout` log at `error`, expected client-facing failures (`auth`, `query`, `unsupported`, `cancelled`) at `warn`, and anything else at `error`. Each log line carries the error code, category, data source, adapter, and path as structured metadata for log-based monitoring.

`defineApiConfig` accepts an optional `onError` hook, invoked for every logged error, so an application can forward failures to its own telemetry (OpenTelemetry, Sentry, metrics) without this package depending on any of them. A thrown hook never affects the response. `createErrorLoggingPlugin`, `ApiErrorHook`, and `ApiErrorContext` are exported for direct use.
