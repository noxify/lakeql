### Studio editor: explicit auto-fill fields and the v2 endpoint contract

The Endpoint Builder now exports `version: "2.0"` and drops the implicit write-timestamp model. Partitioning is a two-state control — Off or By field/custom — and the removed By-write-timestamp mode no longer injects a phantom `load_timestamp` row; an enabled mutation always writes an explicit `partitioning` value.

A write-timestamp column is now an ordinary auto-fill field: a new "Add write-timestamp field" helper adds a real, editable top-level `DateTime` field with `options.autoFill: "write_timestamp"` (default name `load_timestamp`, capped at 58 characters), and the field properties panel shows an auto-fill indicator. The validity gate mirrors the schema's auto-fill rules with field-keyed findings — reserved-name collisions against derived `_year`/`_month` companions, auto-fill valid only on a top-level `DateTime` field, auto-fill requiring an enabled `append`/`full_load_append` mutation, and partition segments that reference a companion column. Importing a v1 definition now fails with a clear "version no longer supported" message instead of an opaque schema error.
