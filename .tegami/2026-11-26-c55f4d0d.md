### First-class auto-fill fields and a v2 endpoint schema contract

**Breaking.** This release changes the endpoint definition format and removes partitioning APIs. It is published as a minor version on purpose, because the 1.x line has not been announced yet. See "Migration" below.

Endpoint definitions now declare auto-fill directly on a field via `options.autoFill: "write_timestamp"`. A write-timestamp auto-fill field must be a top-level `DateTime` field under an enabled `append` or `full_load_append` mutation. It is populated server-side on every write and exposed in the query type and table together with its derived `<name>_year` and `<name>_month` companion columns, while staying out of the mutation input. The schema rejects auto-fill on any other field type, on nested fields, on `full_load`, and when no mutation is enabled. It caps an auto-fill field name at 58 characters so its companions stay within the field-name pattern, and it rejects partition segments that reference a companion column in any form (use the primary field's `name:year` component form instead).

The endpoint schema version is now `"2.0"` (exported as `ENDPOINT_SCHEMA_VERSION`, with an `isSupportedVersion` helper). `"1.0"` definitions and the former `partitioning: true` value are no longer accepted, and there is no compatibility shim. `partitioning` is now `false | string` only. New shared derivation helpers (`deriveAutoFillColumns`, `autoFillCompanionNames`, `findReservedNameCollisions`, `AUTO_FILL_WRITE_TIMESTAMP`) are re-exported from `@lakeql/schema-generator/endpoint-schema` as the single source of truth for companion names.

`@lakeql/datasource` adds an optional `autoFillFields` entry to `DataSourceWriteConfig` so adapters can forward auto-fill directives to the write pipeline.

Codegen (`@lakeql/cli`, `@lakeql/file-generator`) expands an auto-fill field into its primary plus companion columns for the query type, interface and DDL while excluding all three from the mutation input, threads the auto-fill directives into the generated `storageConfig`, and rejects non-`2.0` definitions with an actionable message.

The write pipeline (`@lakeql/storage`, `@lakeql/adapter-trino`) no longer partitions by an implicit write timestamp. When a write carries `autoFillFields`, every schema-writing load (`append`, `full_load_append`) stamps each named field plus its companions from one shared write clock, independently of the partitioning value. The columns are populated and created even when partitioning is disabled; only the on-disk partition path is omitted. An `append` that partitions over an auto-fill field succeeds even when the incoming records do not carry that field, because the field is populated before partition grouping runs. The Trino write strategy forwards `autoFillFields` verbatim and remains the sole DDL author. The removed `enrichJsonSchemaWithTimestamp` and `injectLoadTimestamp` helpers are replaced by `enrichJsonSchemaWithAutoFill` and `injectAutoFillValues`.

### Partition segments: bare names, components and Date fields

A bare partition name such as `region` always partitions by the raw field value (`region=EU`), for every field type. The single-field mode that turned a bare name into a date-based `year=/month=/day=` path is gone, together with `partitioningFormat`.

`Date` and `DateTime` fields are only valid as partition segments with a component, for example `event:year/event:month/event:day`. A `Date` value has no time of day, so `hour`, `minute` and `second` are only valid on `DateTime` fields. A `Date` field accepts `year`, `month` and `day`, exported as `datePartitioningComponents`. A bare date segment, a component on a non-date field, or a time component on a `Date` field is rejected by `endpointDefinitionSchema` with a message that names the fix. A v2 endpoint file that still sets `mutation.partitioningFormat` fails validation (in `create-endpoint` as well) with a message explaining how to migrate.

`@lakeql/schema-generator` drops `partitioningFormats`, `PartitioningFormat` and `MutationConfig.partitioningFormat`, and renames `validatePartitioningFormat` to `validatePartitioningString`. `@lakeql/storage` drops `generatePartitionPath`, `groupRecordsByPartition`, `WritePipelineConfig.partitioningFormat` and the `"field"` partition mode. `PartitionMode` is `"disabled" | "custom"`, and `resolvePartitioningConfig` takes a single argument: an absent or `false` `partitioning` resolves to `disabled`, and a string selects custom partitioning. `@lakeql/datasource`, `@lakeql/file-generator`, the CLI codegen and the Trino write strategy no longer carry `partitioningFormat`.

#### Migration

Endpoint definitions have no automatic migration. For each existing `endpoint.json`:

- Set `"version": "2.0"`.
- Replace `partitioning: true` with a `DateTime` field that has `options.autoFill: "write_timestamp"` (for example `load_timestamp`) and a partition string such as `load_timestamp:year/load_timestamp:month/load_timestamp:day`, or with `false` for no partitioning.
- Remove `mutation.partitioningFormat` and write the date granularity as components in `partitioning`, for example `event:year/event:month`. A `Date` or `DateTime` field always needs a component.
- Regenerate the endpoint with `create-endpoint`.

Code that imports the removed `@lakeql/schema-generator` and `@lakeql/storage` exports has to move to their replacements, listed above.
