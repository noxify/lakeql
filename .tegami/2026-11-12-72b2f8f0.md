### Field-driven auto-fill populate in the write pipeline

The write pipeline no longer partitions by an implicit write timestamp. Auto-fill is now a property of the field: when a write carries `autoFillFields`, every schema-writing load (`append`, `full_load_append`) stamps each named field plus its derived `<name>_year` / `<name>_month` companion columns from a single shared write clock, independently of the partitioning value. The columns are populated and created even when partitioning is disabled; only the on-disk partition path is omitted. An `append` that partitions over an auto-fill field now succeeds even when the incoming records do not carry that field, because the field is populated before partition grouping runs.

`resolvePartitioningConfig` no longer has a timestamp mode: `PartitionMode` is `disabled | field | custom`, an absent or `false` `partitioning` resolves to `disabled`, and a string selects field or custom partitioning. The Trino write strategy forwards `autoFillFields` verbatim to the pipeline; it remains the sole DDL author.

The removed `load_timestamp` helpers `enrichJsonSchemaWithTimestamp` and `injectLoadTimestamp` are replaced by `enrichJsonSchemaWithAutoFill` and `injectAutoFillValues`, which take the declared auto-fill field names and share the schema-generator companion-name contract.
