### Declare technical-user permissions in `lakeql.config.ts`

Technical-user `permissions` are now declared in the project config under `auth.permissions` and forwarded to the API, mirroring how `impersonationResolver` already flows from config to the API layer. You still author the rules in `src/permissions.ts`; import them into `lakeql.config.ts` and pass them to `defineConfig({ auth: { permissions } })`. The generated app's `src/index.ts` reads `project.config.auth?.permissions` and forwards it to `defineApiConfig`, so you no longer import `permissions` directly into `index.ts`.

Scaffolded apps now emit this wiring: `generateLakeqlConfig` imports `permissions` from `./src/permissions` and sets `auth.permissions`, and the app entry (`src/index.ts`) forwards the value from the loaded config and warns when no rules are configured. The `defineApiConfig({ permissions })` option remains the single API entry point that consumes the rules.
