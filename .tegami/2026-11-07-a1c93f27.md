### Fix `generate-import-config` and make `pull --bulk` multi-source

`generate-import-config` now reads the authoritative `sourceConfig` from each generated endpoint's `config.ts` instead of inferring values from the directory layout. The previous scan was one directory level off — it emitted the data source name as the catalog, the catalog as the schema, and never reached the real table directories. Emitted entries now carry the correct `dataSource`, `catalog`, `schema`, and `tables`, grouped per `(dataSource, catalog, schema)`. The `adapter` is no longer emitted, since it is derivable from the `dataSource`.

`pull --bulk` is now multi-source. Without `--source`, every entry is processed and each is resolved against its own `dataSource`; each distinct source is connected once, cached, and closed at the end (even on failure). With `--source <value>`, the flag acts as a filter that keeps only entries belonging to that source. A single-source project may omit `dataSource` per entry (it defaults to the sole source); a multi-source project requires `dataSource` per entry, and omitting it with more than one source configured (and no `--source` filter) is a clear configuration error.

### `BulkPullEntry` gains an optional `dataSource` field

`BulkPullEntry` / `bulkPullConfigSchema` now accept an optional `dataSource` naming the configured source an entry belongs to. It may be omitted in single-source projects and is required per entry in multi-source projects.
