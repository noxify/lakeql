### Stop pulling prettier and files-sdk into production installs

Two misplaced dependencies that bloated production installs of scaffolded apps have been corrected:

- `prettier` and `@ianvs/prettier-plugin-sort-imports` are no longer runtime dependencies of `@lakeql/helpers`. They are only needed by the `@lakeql/helpers/format-code` export, which is consumed exclusively by `@lakeql/file-generator` (a CLI-only, dev-time tool). They now live in `@lakeql/helpers` dev dependencies and are declared as runtime dependencies of `@lakeql/file-generator`, so the formatter no longer lands in an app's production dependency closure.
- `files-sdk` is now an optional peer dependency of `@lakeql/adapter-trino` and `@lakeql/storage` (range `^3.1.2`). Both packages import it type-only, so the built output never requires it at runtime. Consumers only need to install `files-sdk` if they use the write pipeline; read-only consumers no longer pull in its heavy transitive graph.
