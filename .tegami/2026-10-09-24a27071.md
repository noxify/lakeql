### Add the `lakeql add <feature>` command

The CLI can extend an existing project with a named feature on demand. `lakeql add <feature>` reads only the project's `package.json` from the invocation directory — it never loads or executes `lakeql.config.ts`, so applying a feature never triggers the project's env or adapter validation. It looks up the feature template, resolves any inputs the template declares, checks its preconditions, and applies the additive changes idempotently: it installs missing dependencies, appends new `.env.example` keys, and writes new files without overwriting existing content. The two edits that touch user-owned source (`env.ts` schema and `lakeql.config.ts` wiring) are printed as guidance rather than applied, followed by the feature's next steps.

- `--dry-run` previews every change without writing;
- `--source <name>` supplies a feature's data-source input non-interactively; when omitted on an interactive terminal the command prompts for it, and feature guidance stays generic when no source is given;
- an unknown feature id fails with an actionable error listing the available features, and a directory with no `package.json` fails before anything is written.

The first shipped feature is `fabric-obo`, which wires up the Fabric On-Behalf-Of impersonation flow.
