### Sharper `overrides` typing for adapters without registration options

The `overrides` field of a data-source entry is now aware of whether the
selected adapter actually declares registration-level options.

- Adapters that declare real registration options are unchanged: `overrides`
  still accepts `Partial<TOptions>` with full per-field autocomplete and
  type-checking.
- Adapters that declare no options (such as Trino and Fabric, whose options
  type is `unknown`) no longer surface `overrides` as the meaningless
  `Partial<unknown>`. The field now collapses to `never`, so autocomplete
  offers nothing and assigning an arbitrary object is a type error instead of
  a silent no-op.

Existing configurations that omit `overrides` continue to type-check
unchanged. A new exported helper type, `OverridesFor`, encapsulates this
behavior. This is a compile-time typing refinement only — runtime merge
behavior is unchanged.
